# Powder Doser — CADSmith full-workflow output

This directory holds the CAD generated by running the **full CADSmith
workflow** (Planner → Coder → Executor → Validator → Refiner loop) over the
self-contained engineering prompt in
[`data/prompts/powder-doser-assembly-prompt.md`](../../data/prompts/powder-doser-assembly-prompt.md)
(issue #5).

The device is the Vertical Cloud Lab **Powder Doser**: an auger-fed,
screw-metered dry-powder dispenser. Each 3D-printed part was generated
**part-by-part** as an independent manifold solid, then a representative
**assembly** (tilt = 0°) was generated to show the shared-datum layout.

## How it was produced

```bash
export ANTHROPIC_API_KEY=...
export AUTOFAB_BASE_MODEL=claude-opus-4-5      # Opus as the base model
xvfb-run -a python scripts/run_powder_doser.py # all parts + assembly
```

- **Base model (all agents): `claude-opus-4-5`** (Claude Opus — the latest
  available Opus; the issue's "Opus 4.8" predates any released build, so the
  newest Opus was used). The vision Judge runs on the same Opus model.
- The runner ([`scripts/run_powder_doser.py`](../../scripts/run_powder_doser.py))
  splits the master spec into focused, self-contained per-part prompts that
  carry the shared datum and tolerance context (§1, §6, §7), runs the full
  agentic loop on each, and is resumable (a part with a `result.json` is
  skipped on re-run).

## Layout of each part folder

| File | Contents |
|------|----------|
| `model.py` | Final CadQuery source that builds the part (`result`). |
| `part.step` | Authoritative STEP export (manifold solid). |
| `render.png` | Three-view Judge render (isometric / high-angle rear / front profile). |
| `result.json` | Full pipeline log: plan, every iteration, validation feedback. |

For the assembly, an extra `iso/` folder holds **full-assembly renders at
several isometric angles** (four corners plus a top-down and a low-front view),
plus a tiled `assembly_iso_contact_sheet.png`. Regenerate them with:

```bash
xvfb-run -a python scripts/render_assembly_isos.py
```

`part.stl` and the per-iteration scratch (`_work/`) are intentionally
**not committed** (meshes are regenerable from the STEP / `model.py`, and one
tessellated thread mesh exceeded 80 MB). Re-export an STL with:

```python
import cadquery as cq
cq.exporters.export(cq.importers.importStep("part.step"), "part.stl")
```

## Notes & caveats

- The **assembly** is a single representative solid that places the major
  parts on their common datum (auger axis at Z = +29.25 above the plate top,
  axis along +Y); off-the-shelf parts (NEMA 11, MG996R servos) are modelled as
  envelopes, and gear teeth are simplified to bands for the assembly view.
- **`auger_cap`** prints and is watertight, but the printed internal thread
  vs. the auger's external thread is the trickiest fit in the set; re-run with
  a larger `--max-refinements` to push it to full Judge convergence.
- Printed gear teeth are involute approximations from the Coder; treat the
  STEP as the geometric reference and add ~0.15 mm backlash per §7 before
  printing.
